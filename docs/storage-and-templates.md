# 数据目录与图片皮肤模板

## 一处管理全部创作数据

默认目录为项目下 `4dgen-data/`，不再把源模型和皮肤包分别保存在缓存与管理器目录里。

| 子目录 | 内容 |
| --- | --- |
| `sources/` | 导入的模型、贴图、上传文件、模板原始图片 |
| `models/` | 模型 ID、编辑配置、版本关联、原有 ZIP 解包资料 |
| `skins/` | 本地皮肤包、历史修订、游戏安装记录与备份 |
| `cache/` | 可重建的解析结果、预览与临时导出 |

备份时退出程序，复制整个数据目录。Minecraft 的 `skin_packs` 是安装目标，保持独立；不要将创作数据放进游戏目录。原来的 `skin-manager.local.json` 继续配置游戏位置，其中 `stateDir` 仅作为旧数据导入来源，网页、`packs` CLI 和 workflow 最终使用统一目录下的 `skins/`。

页面顶部的“数据目录”可设置新的空目录。保存设置后重启服务，程序复制现有数据、修正模型与图片路径，保留旧目录。程序仍在运行时继续写入旧目录，重启时才复制最终状态。默认配置保存在 `storage.local.json`：

```json
{ "dataDir": "D:/4DGenData" }
```

也可用 `FOURDGEN_DATA_DIR` 覆盖目录；此时网页不修改路径。通过环境变量自行换位置时，请先整体复制数据并保留 `storage.local.json` 的迁移流程，或直接使用网页搬家。不要直接只修改路径指向空目录并删除旧数据。

启动时复制旧的 `.cache/model-library`、`.cache/web-uploads` 与配置中的皮肤包管理目录，保留原件。旧的外部模型引用会把模型及相关贴图复制进 `sources/local/`，保留模型 ID、配置和版本关联。源文件已经丢失的条目仍可重新定位，重新打开后归档。新导入的本地模型会复制所选模型及目录内贴图/资源；不复制其他模型、符号链接、`.git`、`node_modules`、`.cache`。文件上限为 2000 个、256 MB，建议模型放在独立目录中。

本地皮肤包保存、整理与导出不要求配置 Minecraft。配置游戏目录后，同一份本地收藏可加入游戏，无需重新导入。重启程序后再更改游戏安装配置。

## 图片模板

打开“皮肤模板”，选择图片、名称和高度，点击生成。平面保持图片比例，为竖直、双面 `poly_mesh`，共 4 个三角面，绑定身体；可用鼠标旋转检查。默认高度 32，约等于玩家高度。正面保留图片方向，背面为纸张背面效果。

支持 Sharp 可解码的常见图片，上传限制 20 MB、解码限制 4000 万像素。保留透明背景、自动应用照片朝向；动画图片使用第一帧。完整图片缩放到 128×128 贴图内，不裁切、不拉伸，狭长比例可能需要先裁切。成品受最终纹理分辨率限制。

生成后直接下载 `.zip`，或使用和模型转换相同的“保存皮肤”弹窗，保存为独立包或复制到合集。在独立图片包中点击“继续编辑图片皮肤”可重新载入保存的源图片与高度。修改后另存为新版本；不自动覆盖已启用内容。合集内的复制皮肤不带独立编辑记录，源版本仍会保留。

文件结构和离线预览已验证；图片模板是新几何布局，仍需在目标 Minecraft 客户端确认实际穿戴效果。

## 验证

```sh
npm run check
npm run check:web
npm run test
npm run test:studio
```

`test:studio` 使用临时数据目录和未配置游戏的本地收藏，验证图片模板、源模型归档、命名保存、源图保存、ZIP 下载及游戏写入阻止，结束后删除测试数据。
