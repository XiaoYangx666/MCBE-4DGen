# Windows 客户端测试记录

记录 Minecraft Bedrock（Windows）上 1.8.0 `poly_mesh` 皮肤包的加载与显示观察。测试使用两个公开 CC0 样本：Avocado（静态绑定，682 三角形）与 Shino（VRM 人形绑定，含双面约 5.2 万三角形）。源模型、生成包与部署快照均留在本地忽略目录，不纳入仓库。

> 早期几轮曾把测试包写入 `persona` 槽位。自包管理器与只读策略落地后，4DGen 只写 `custom`，不再写入 `persona`；下文保留 `persona` 仅用于说明当时的对照条件。

## 第一轮：基础部署与校验

- 两个目标目录（`custom`、`persona`）均通过 `validate`，部署后的纹理与几何 SHA256 与生成文件一致。
- 保留原 manifest UUID 与 `skins.json` 包级标识。
- 部署/恢复往返在隔离目录中验证，恢复后原文件字节一致；备份包含原文件与哈希，恢复前会校验备份与当前部署文件，检测到后续修改时拒绝覆盖。
- 测试观察：游戏内未出现皮肤条目。此时只完成文件级校验，不能据此判断客户端是否接受该几何。

## 第二轮：JSON 兼容性

- 对照参考皮肤包的清单结构，同时调整多项候选：两个包使用独立 UUID、版本 1.0.1、独立几何 ID（`geometry.fourdtest_avocado` / `geometry.fourdtest_shino`）；`custom` 去掉 `skins.json` 包级字段；`persona` 使用 manifest `format_version: 1` 并保留 `serialize_name: Standard`。
- 多项同时调整，不能把结果归因到某一个字段。
- 校验结果：JSON、几何引用、UUID 唯一性与纹理哈希通过。`persona` 的版本 1 清单超出本项目校验器只接受版本 2 的范围，未声称该校验器通过。
- 测试观察：包标题出现，模型区域仍为空。

## 第三轮：诊断条目

- 每包增加四个命名条目：标准人形（64）、参考模型（128）、生成模型缩小贴图（128）、生成模型原贴图（512/1024）。复制参考几何时只在内存中去掉参考文件末尾的逗号，不修改参考包。
- 补全唯一 `serialize_name` / `localization_name` 与 `en_US` / `zh_CN` 名称，版本升为 1.0.2，保留上一轮 UUID；诊断条目不设置 `hide_armor`。
- 校验：四个条目的 PNG 尺寸、几何引用、贴图尺寸一致性与骨骼父引用均通过。
- 该轮用于区分标准皮肤加载、`poly_mesh` 支持、生成数据兼容性与贴图尺寸限制，当时尚无客户端结论。

## 第四轮：贴图尺寸对照

- 测试观察：标准人形、参考模型与 128 贴图的生成模型均可见；原尺寸 Shino 未显示，原尺寸 Avocado 显示为灰色人形。
- 同一包内 128 与原尺寸生成模型的几何数据相同，仅贴图尺寸与引用不同，因此结果支持「最终贴图尺寸」是这两份模型未正常显示的原因。
- 后续用图片模板单独测试了 256/512/1024，均不可见，见文末「图片模板贴图尺寸」。
- 修复：exporter 增加可选 `skinTextureSize=128`，限制最终贴图并同步几何尺寸，保留 normalized UV 与原网格；回归测试覆盖缩小图集后的引用与源贴图不变。
- 结论：128×128 是客户端确认可显示的唯一尺寸。

## 人形动作绑定

- 测试观察：模型可穿戴，但四肢静止在 T 姿势；原实现为整体挂到 body。
- 实现：新增 CLI `--binding humanoid`。VRM 0/1 humanoid 节点标记经 importer 保留，原始权重按每个三角形的总权重归属分到六个玩家骨骼；肩、髋、头关节经同一高度/居中变换后作为枢轴；按肩到手方向把手臂几何与法线转到向下姿势。共享关节处为刚性接缝，不保留平滑权重、肘膝弯曲或物理。
- 数据：Shino 原始 31211 面，六部分 body=3653 / head=20664 / leftArm=1937 / rightArm=1937 / leftLeg=1502 / rightLeg=1518，含双面最终 52106 面。生成文件与 mcpack 交叉校验通过；128 PNG 离线四视图手臂下垂。
- 测试：新增两项人形测试，覆盖六部分归属、源枢轴降低双臂、源输入不变与缺失必需角色拒绝；另有 19 项几何/导出/准备测试与类型检查通过。
- 仍未验证：走路、挥手、转头与装备隐藏的实际表现。

## 手臂间距调校

- 测试观察：绑定生效，但静止姿势下前臂藏入身体。旧版每侧肩枢轴 X 约 2.114，竖直前臂的 X 范围落入躯干/裙子。
- 参考：安装文件中的 `animations.brarchive` 为打包归档，没有直接 JSON；参照 Mojang 官方 bedrock-samples 的 `player.animation.json` 与 `humanoid.animation.json`，待机 Z 摆动约 0–5.73°，走路主摆臂绕 X，持物还会叠加偏转。未替换游戏动画。
- 调整：为模型增加独立 profile，每侧肩外移 1.2、静止姿势外展 12°，几何与肩枢轴一起外移；其它模型默认仍为 0/0。
- 数值抽样：排除肩下 3.5 单位以内的接合区域，对前臂顶点与躯干/裙子顶点按 Y ±0.4、Z ±0.6 的邻域比较侧向间距，并叠加向内 Z 5.73°，采样 X=0/±40°。旧版站立左/右最小间距 -2.928/-2.838，调校版 +0.189/+0.417；X=40° 时两侧均为 +1.038，X=-40° 时前臂不在躯干采样邻域。
- 限制：这是顶点邻域抽样，不是三角形碰撞证明，也不覆盖全部原版动作；游泳、盾牌、弓箭等动作未验证。

## 衣物归属与源权重姿势

- 测试观察：袖子错位，裙子在走路时随单腿摆动。
- 源文件检查：独立下装材质 700 面；裙骨（前/后/侧）父级为 UpperLeg，旧祖先映射会把裙骨错误归为腿。上衣材质含 22 个按原索引拓扑区分的连通部分，既有躯干/领口，也有混合胸/肩/臂权重的袖子。
- 修改：先调整源关节姿势，再基于原始平滑权重计算静止姿势，替代冻结后直接移动硬切片。profile 显式指定下装全部归 body；上衣按连通部分累计权重分类，肩骨在衣物分类中计入同侧手臂。每侧袖子 410 面、上衣躯干 1245 面、裙子 700 面归 body。
- 新面数：body=4067 / head=20374 / leftArm=2019 / rightArm=2019 / leftLeg=1366 / rightLeg=1366，总面数仍为 31211，双面后 52106。规则未命中或重复归属会直接失败；源 VRM 未被修改。
- 离线检查：骨骼归属图与 ±35° 摆臂/摆腿示意（不是 Minecraft 动画回放）显示静止肩袖连续性改善。
- 仍未验证：刚性运行时袖口接缝、裙子与腿的穿插；尚未实现布料物理。

## 收窄肩部与静止姿势

- 每侧肩外移由 1.2 降至 0.5，外展由 12° 降至 6°；保留源权重姿势计算与材质归属规则。
- 生成包通过交叉校验；六部分面数与材质分类不变，肩枢轴间距约减少 1.4 模型单位。
- 离线四视图手臂更贴近身体且仍可见手掌；待机叠加摆动与实际动作穿插仍未验证。

## 固化为工作流

- 新增 `npm run workflow` 与 `npm run packs`，主文档为 `docs/workflow.md`。目标 root 与 slot 清单格式由配置指定，管理状态保存在统一数据目录；默认只转换、预览并入库，显式 `--deploy` 才写游戏目录。
- 本地库支持目录/mcpack 导入、导出、启停、多包名称与几何隔离、完整备份、基线/历史恢复与中断恢复。
- `4dgen-data/skins` 是持久管理数据，不能按缓存清理；旧版 `.skin-pack-manager` 会在首次运行时导入。旧实验脚本移至 `scripts/experiments/`。
- 回归：`npm run test:workflow` 37/37 通过，包含 CLI 子进程测试（需在允许启动子进程的终端执行）。未声称完整原生 Assimp 套件通过。
- 在隔离目录跑通静态模型与 VRM 的完整 `--deploy` 往返，并恢复原始空包；多包合并后的游戏端展示仍需实际确认。

## 图片模板贴图尺寸（2026-10-22）

- 样本：一张 1252×1009 的透明 PNG，通过图片模板生成同一几何的 128/256/512/1024 四个条目，合并为一个测试包。
- 文件校验：四个条目的 PNG 与 geometry 尺寸一致，均为 4 三角面，包结构通过。
- 客户端结果：只有 128×128 条目显示；256/512/1024 均不可见。
- 结论：图片模板与 3D 导出统一固定 128×128，更大贴图不作为支持范围。
