# 本地网页工作台

```powershell
bun install --frozen-lockfile
bun run dev
```

打开 http://127.0.0.1:4173 。一个 Node 进程在启动时调用 Vite 构建 React 页面，再同时提供静态资源与转换 API；不需要另开前端或后端进程。关闭终端或 Ctrl+C 停止。修改网页源代码后重启即可重新构建；当前版本没有 HMR。

## 应用页面

统一顶栏提供「源模型 / 工作台 / 皮肤模板 / 皮肤包 / 设置」。页面切换保留当前工作台的调整和转换结果。

- **源模型**：搜索、按名称或最近编辑排序、筛选有源模型/有皮肤版本的内容。左侧选择模型，右侧查看源模型 3D 预览、皮肤版本或模型信息；支持重命名、继续编辑、移出模型库。
- **工作台**：材质、姿势、减面、图集与转换。顶栏「保存配置」持久化绑定、比例、误差、高度、材质排除、像素权重与 profile；生成时也保存配置，重新打开模型恢复这些值。
- **皮肤模板**：把图片制作成可编辑的双面平面皮肤模板，保存到统一数据目录。
- **皮肤包管理**：左侧「我的皮肤包」顶部搜索，custom / persona 为置顶预制包，读取游戏目录里的真实皮肤；下方仅列出独立本地皮肤包，接管游戏预制包时保存的来源副本不重复展示；后来加入游戏的用户包仍显示并标注游戏中。包列表不显示预览图，游戏中状态直接标在条目上。右侧列出包内皮肤，选中皮肤才显示三维预览。支持新建空包、导入 ZIP/ZIP/本地文件夹、复制指定皮肤到本地包、中文包名/皮肤名修改与删除。预制包不可删除，已加入游戏的本地包需先移除才能删除。
- **设置**：外观、游戏目录、数据目录、占用统计，以及「关于 4DGen」弹窗（版本、运行环境与数据目录）。

## 导入与编辑

1. 源模型页使用紧凑工具栏，搜索框占主要宽度，筛选/排序保持窄宽度。「获取模型」打开按类型分类的模型网站目录：默认按常用程度排列，模之屋置顶；支持搜索、类型切换和网站图标，点击卡片在新标签页打开。点击「导入模型」。输入本地环境 ZIP、模型或文件夹绝对路径，由服务器直接读取；也可选择文件或贴图文件夹。包内有多个模型时先选择角色，武器不作为人形模型导入。工作台不提供导入或拖入导入；请从源模型页导入并打开模型。
2. ZIP 解压保存在 `4dgen-data/models/packages`，管理记录位于 `4dgen-data/models/entries`。直接导入的模型/文件夹会连同贴图复制到 `4dgen-data/sources/local`，原始下载文件可自行管理；相同 ZIP 复用解压，解析结果和预览均有磁盘缓存，模型或旁边贴图的大小/修改时间变化会失效。
3. 在「源模型」查看预览，点击「继续编辑」进入工作台。VRM 元数据和常见 MMD 骨骼自动映射；不确定、重名、缺失或无有效手臂链时保持静态模式，可手动提供 boneMap。
4. 材质勾选影响输出，「只看」仅影响观察。手臂、肩部、朝向和高度即时预览；减面和像素权重在生成后查看。右下角「按住看原始」可临时对照。
5. 生成后点击「保存为皮肤版本」，直接进入当前模型的「皮肤版本」页。填写可选中文版本名，选择仅保存或保存后启用；默认仅保存。每个版本显示 3D 预览、面数、贴图和转换设置，可按此版本配置再次编辑、启用或删除。
6. 新版本通过稳定模型 ID 关联。历史皮肤包仅在来源名称唯一命中时自动归属，否则显示为「待关联源模型」，可手动选择模型关联。无法找到源模型的旧包仍可预览与启停。已有库数据不清空。
7. 「移出模型库」删除管理记录和编辑配置，保留原文件、缓存和皮肤版本。删除皮肤版本为永久删除，必须先停用；界面会再次确认。

新建包可以先命名，添加皮肤前不能加入游戏；添加到本地包复制所选皮肤，来源包保持不变。选择预制包时，「添加皮肤」将选定本地包的全部皮肤加入游戏，必须先退出 Minecraft。预制包的「恢复初始」和中断恢复操作保留在包详情中。

皮肤包名称和皮肤名称会写入 manifest 与各语言文件，并生成新修订。改名只保存到本地包，已启用的修订保持不变；页面会显示「更新名称到游戏」。其他包的启停仍可读取旧修订，避免改名影响正在使用的包。

启用、更新、停用、恢复之前请完全退出 Minecraft。管理器继续执行 SHA256 校验与外部改动保护。

## 本地服务与桌面封装

React 页面按源模型、工作台、皮肤模板、皮肤包和设置拆分；页面状态与操作分别由 `useWorkbench`、`usePackPage` 管理，预览复用 Viewer 和 PackPreview。文件操作集中在本地服务器，前端通过 `web/lib/api.ts` 调用接口；Electron 桌面版复用这些页面，由 `desktop/main.cjs` 启动私有后台服务，打包与检查见 [桌面版](desktop.md)。

## 范围

- 转换复用正式模块；紧凑图集默认按世界表面面积 × 材质权重分配目标矩形面积，保留至少 3×3 的采样尺寸；打包、边距和像素取整会影响实际比例。负数/跨边界 UV 按 repeat/mirror/clamp 采样其连续使用区域，不再因此拷贝整张源图。内部遮挡面仍会计入面积，不代表完整可见性分析；样本 B色块仍需视觉验收。
- 材质筛选是人工选择，`表情` 快捷按钮只供对照，不会自动判定所有模型的隐藏材质。
- PMX 内嵌的 TGA 贴图会在导入时转换为 PNG（Assimp 原样传出，浏览器与导出器都不支持 TGA），因此预览和转换都能使用这些贴图。
- 没有 UV 手绘、图集区域拖拽或玩家动作模拟。材质列表右侧现在支持相对像素权重，范围 0–20，默认 1；调整后重新生成。
- Three.js 预览使用实际导出几何和贴图，仍不能替代 Minecraft 渲染与动作验收。
- 本地示例只在源文件存在时显示；样本 B当前优先使用同目录诊断 GLB 缓存以缩短导入耗时。该缓存没有 PMX 原始来源语义，示例用于本地环境对照。
- 文件不上传云端。上传文件留在忽略的 `4dgen-data/sources/uploads/`；会话与结果保存在内存，重启后失效。最多保留最近四个模型、八个生成结果，旧会话自动释放。
- 只监听回环地址，变更接口检查同源与 Host；上传相对路径检查目录穿越。单次上传/解压内容限制 256 MB、2000 个文件。
- 皮肤包管理直接复用 `src/pack-manager.ts` 与 `skin-manager.local.json`：写入前做 SHA256 校验，拒绝管理器之外的改动和链接路径。网页操作成功后只保留槽位的初始基线，历史写入快照会被清理；「恢复初始」即可回到原始皮肤包。库中同时保存生成时的来源模型、绑定、减面、高度、排除材质与 profile；网页提供 `.zip` 下载，也可用 `bun run packs export` 导出 ZIP。未创建配置文件时面板只显示提示，不执行任何写入。

## 面数、误差与性能

- 工作台只保留「调整预览」与「转换结果」两个标签。调整预览统一处理材质、姿势与朝向；右下角「按住看原始」临时还原姿势和朝向，松开恢复，保持当前高度、材质筛选和视角不变。支持鼠标、触摸以及空格/回车按住对照；失焦时自动结束对照。减面与像素权重仍需转换后查看结果。

- 网页面数提示以最终三角面（含双面）计数。建议参考样本 B轻量版 35,122 面，见 `pmx-model-tests.md`；测试确认 Shino 为 52,106 面，见 `windows-client-test.md`。因此约 3–5 万面不提示超量；仅超过 52,106 面时提醒超出已验收样本参考范围、需实机确认，不宣称无法加载或引擎上限。样本 B 203,145 面重版有加载困难反馈，但原因未确认。估算与实际输出均使用此规则。

- 比例下方显示「目标约 N 面」：按当前勾选材质、双面输出和保留比例估算。人形减面会扣除完全透明的壳层。误差约束、清理、部位分组会影响实际面数；上次实际面数另行显示。
- 「形状变化容限」收进高级减面设置。默认 0.03；调小更保形但可能减不到目标，调大更容易减面但可能破坏轮廓。该值相对 Meshoptimizer 的 primitive 尺度，不是模型必然变形的百分比。
- 转换状态显示阶段和已用时，报告记录总用时及人形各阶段耗时；完全相同参数会复用仍在内存中的结果。
- 人形六部位现一次导出，贴图按图复用解码。相同样本 B样本本地测量约 28 秒 → 8.3 秒（排除表情、ratio=.2、maxError=.03；不含导入），不是所有模型或机器的保证。
- 2026-10-18 第二轮本地测量（同一样本 B样本，缓存 GLB 导入，`scripts/diagnostics/bench-convert.ts`，5 次取中位数）：总耗时约 13.5 秒 → 4.4 秒，其中冻结姿势约 5.2 秒 → 1.8 秒、图集约 5.3 秒 → 1.3 秒；样本 A样本约 2.7 秒 → 1.1 秒。三处热点：顶点冻结循环中每顶点分配矩阵/数组/拼接字符串；图集按岛重复解码多兆像素源图（缓存上限小于源图数量）且逐个串行重采样；模型校验对每个属性分量使用 `Array.every` 闭包。三项均未改变输出：同一输入导出几何、`skin0.png`、骨骼枢轴与部位面数在改动前后逐字节一致（`scripts/diagnostics/fingerprint-convert.ts`）。本地环境为 16 GB 内存的 Windows 环境，单次测量波动约 ±15%（GC 与线程调度），比较应以中位数为准。
- 样本 A的旧 UV 包围框相交合并会把稀疏岛连成大矩形；现在只在合并增加的包围空白不超过 10% 时合并，并有限调整矩形长宽以更好打包。同配置对照包间空白约 17.2% → 3.7%，实际非透明 UV 覆盖约 45.5% → 46.1%。UV 岛内部仍有未用区域，不能把 96% 矩形分配率当成 96% 有效纹理。
- 2026-10-18 第三轮：人形绑定原先为取得高度缩放完整烘焙两次初始姿势，第一次的结果用完即弃。现在改为只测量冻结后的包围盒（`measureFrozenBounds`），与真实烘焙复用同一段蒙皮数学，因此高度缩放完全相等。交错 A/B 测量（同一环境、各 3 次取最小值）显示冻结姿势约 1135→1058、1335→1126 ms，即 80–210 ms 收益，总耗时差异落在噪声内——这一轮的收益远小于第二轮，不要按比例外推。两个模型导出几何、`skin0.png`、骨骼枢轴与部位面数仍逐字节一致。
- 基准脚本在每轮结束后释放克隆文档并调用 `globalThis.gc`，同时报告最小值和最大值：此前不回收导致堆持续增长、越跑越慢，中位数会随运行轮数漂移。判断改动时应看最小值，中位数只在同一批测量内部可比。测量期间不要同时运行 `bun run dev` 等占用 CPU 的程序。
- 2026-10-18 第四轮：顶点冻结阶段为 `_SOURCE_SKIN_REGION` 标签逐顶点拼接影响签名（每顶点 3 次 `join`），34 万顶点 × 两次遍历即约 200 万次字符串构造。改为对关节索引与权重位模式做双 32 位哈希，分组数量与原字符串签名完全一致（样本 B 6403 组）。交错 A/B（各 3 次取最小值）：冻结姿势 1260→949、1301→1028 ms，稳定节省 250–310 ms；两个模型输出仍逐字节一致。该标签只用于让减面保护原始骨骼边界，不参与贴图或几何数值。
- 本次按测试要求未打开浏览器或执行网页操作。姿势、估算、导出、UV 采样使用代码测试和本地模型检查；交互与游戏效果由用户手动验收。


## 视角、布局与输入调整

- 切换单材质观察或姿势不自动聚焦，相机方向、位置和观察中心保持；需要重新居中时点击「全景」。
- 独看状态保留在材质行的按钮中，不再在列表上方插入「恢复全部」提示。
- 桌面布局限制在屏幕高度内，材质列表利用左栏剩余空间滚动，报告和设置区独立滚动。
- 网页加载示例时肩部外移默认 0；CLI profile 源文件不变。
- 权重允许 0，可先清空、输入小数，再失焦或按 Enter 提交。0 不会移除材质，只使用最低采样预算；需要移除请取消勾选。


## 2026-10 工作流整理

日常流程按以下顺序操作：

1. **源模型**：导入模型及贴图，选择模型进入工作台。这里保留模型路径、编辑配置和已生成版本的关联。
2. **工作台**：调整材质、姿势、面数，点击生成。修改参数后，上次结果会标为过期，需要重新生成才能保存。生成会保存编辑配置；也可单独点击顶部“保存配置”。
3. **保存皮肤**：在工作台直接命名，保存成独立皮肤包，也可以同时复制到已有合集。独立版本保留来源与本次参数；保存不会启用游戏皮肤。无需回模型页面寻找保存入口。
4. **皮肤包 / 本地皮肤包**：查看成品、修改名称、复制皮肤到合集，或导出 `.zip`。空包需要先添加皮肤才能导出。
5. **皮肤包 / 游戏中**：查看游戏安装位置及内容。需要使用时，从本地包点击加入；本地包修改后需要手动更新到游戏。移除游戏中的包不删除本地包。

工作台保存弹窗还可直接下载当前转换结果，即使尚未配置皮肤包管理路径也可使用。下载的是当前已生成的成品，包含几何、贴图、清单和本地化文件。

### 源文件位置与恢复

本地环境模型及贴图在导入时复制到统一数据目录，上传文件和 ZIP 解压内容也在该目录内保存。源文件丢失时，模型页会提示，可在“重新定位源文件”中填写同一个模型的新绝对路径，保留模型 ID、编辑配置与历史版本。已有皮肤包不依赖源文件继续存在。

关闭或刷新页面前，未保存配置会触发浏览器提醒。页面内切换栏目保留工作台状态；打开另一个模型前会提醒是否放弃未保存配置。转换结果仍属于本次服务会话，长期保留请保存为皮肤包或下载。


## 游戏包直接管理与设置

- 在“游戏中”选中皮肤，直接重命名或移除；包头可以修改游戏中的包名。操作只修改游戏副本，本地包保留。移除会清理不再使用的贴图与几何，保留操作备份；“恢复初始”回到接管前内容。
- 游戏中的改名和移除记录随安装位置保存，更新或加入其他本地包不会覆盖它们。再次添加已启用的本地包可重新加入其中被移除的皮肤。
- 源模型详情顶部提供“删除模型”。确认时可选择同时删除程序归档的源文件及独占贴图；原始下载文件、共享源文件和已生成皮肤包保留。
- 独立“设置”页配置 Minecraft 的 skin_packs 目录，保存后立即生效；不同安装目录共用本地皮肤包，但管理状态和备份互相隔离。
- 数据目录也在设置页配置，选择空目录并重启服务后自动复制原有数据，保留旧目录。环境变量 FOURDGEN_DATA_DIR 优先于页面配置。

设置页的游戏目录与数据目录可通过“选择文件夹…”打开 Windows 系统选择器，选好后再保存。数据目录显示按文件大小统计的总占用、分类明细、文件数和磁盘剩余空间，支持手动刷新，统计不跟随目录链接。
