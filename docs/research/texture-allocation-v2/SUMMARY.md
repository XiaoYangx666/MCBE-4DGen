## 最重要的结论

1. **现有权重不是纹理密度控制。** 桌面端合并区域对 0.25×～4× 完全无响应（1.00×）；
   网页版小材质存在 0.25× 与 1× 结果相同的死区；桌面端睫毛 16 倍权重只换来 +6.9%。
2. **矩形内 17%～34% 的像素从未被采样。** 128×128 下每模型约 4 000～7 000 px。
   提高 `allocated utilization` 不是优化方向。
3. **细节材质被系统性饿死。** 眼睛/面部的采样比比服装低 16～55 倍，
   这是「按世界面积」分配的直接后果。
4. **新预算模型解决了控制与利用率，但没有免费提升默认画质。**
   - 权重单调、无死区（floor 除外），相对密度严格由权重决定；
   - `allocated` 稳定 96.4%～97.8%（生产 89.2%～96.7%），C 的平均 UV 覆盖 +4.2 个百分点；
   - `tiny-islands` 从 0.4% 提升到 72%；
   - 但固定视角整图误差比基线差 3%～12%（2/3 个模型），
     因为基线按屏幕面积分配本来就是平均误差的近似最优。
5. **retention 是「细节优先」模式，不是更好的默认值。**
   眼睛误差 −81%～−89%，面部 −13%～−49%，头发 −8%～−16%；
   代价是大面积服装 +5%～+15%。
6. **安全共享（源像素完全相同）在 6 个真实模型中没有触发**；合成角色只省 63 px。
   桌面端的激进合并省得更多，但正是权重失效的根因。

## 推荐

- 采用共享核心（分析 → 预算 → 可选安全共享 → 装箱 → 重映射）。
- **默认保持 legacy**；`atlasBudget` 作为可选模式。
- 若做 UI，只暴露：材质纹理密度倍数（0.25～4）、预算目标（density/retention）、
  安全共享开关、图集尺寸，以及 floor/预计像素/浪费的诊断。
- 不具备「直接替换默认」的条件；具备「可选集成」的条件（已验证 43/43、81/81 矩形一致，
  0 UV 越界，339 个测试通过）。
