# 第四阶段：综合评估与架构选择

> 分支 `research/texture-allocation-v2`
> 数据：`data/stage1-*.md`、`data/stage3-*.md`、`data/stage3-summary.json`
> 固定视角：`images/`（参考 / 候选 / 差异）

## 1. 结论摘要

**现有算法不应该被整体替换，但它的「分配 + 装箱 + 重映射」应当被共享核心替换，
并以可选模式逐步启用。**

理由：

1. 新预算模型在**控制性**上是严格改进：没有死区、没有合并导致的 0 响应、
   权重与纹理密度单调相关（第 4 节）。
2. 新模型在**空间利用率**上是改进：`allocated` 稳定 96.4%～97.8%（生产 89.2%～96.7%），
   UV 覆盖在 5/6 个模型上不低于网页基线，`tiny-islands` 从 0.4% 提升到 72%。
3. 新模型在**默认视觉质量**上没有优势：固定视角误差比基线差 3%～12%
   （shino/nana），只在 furina 上更好。原因不是实现缺陷，而是
   「按源纹素保留」与「按屏幕面积」本来就是不同的目标。
4. 桌面端的激进合并虽然牺牲控制，却换来了更好的装箱与大面积材质质量；
   在没有 UI 让用户表达优先级之前，直接换默认会让一部分模型变差。

因此推荐：**共享核心 + 默认保持 legacy + 提供可解释的预算模式**。
这不是「新算法更好所以替换」，而是「新架构让用户能控制，且不牺牲正确性」。

## 2. 证据强度与限制

| 证据 | 强度 |
|---|---|
| 两个生产规划器的移植与生产逐项一致 | 强（11/11 场景、120/120 矩形） |
| 权重响应的死区/零响应 | 强（0.25/0.5/1/2/4 扫描，6 模型 + 11 场景） |
| 利用率对比 | 强（同一渲染器、同一测量、确定性） |
| 逐材质质量 | 中（以源纹理双线性采样为参考，非人眼评估） |
| 整图视觉质量 | 中（固定正交视角、无光照、单一相机） |
| 结论适用范围 | 动漫角色（PMX/VRM 派生），128×128，14～27 材质 |

未覆盖：写实 PBR、硬表面、透明/次表面材质、多相机视角、动画变形；
也未做用户可用性测试。真实模型素材不入库，复现需要相同素材（记录 SHA-256）。

## 4. 九个问题的回答

### 4.1 哪些问题已经通过实验确认？

1. 权重在现有实现里**不是密度控制**：桌面端合并区域 0.00 响应；
   网页版小材质在 0.25× 与 1× 结果相同；桌面端睫毛 16 倍权重只换来 +6.9% 密度。
2. 跨材质合并会**合并预算**（`shared-texture` 合成场景与真实模型 7～12 个岛）。
3. 矩形内 17%～34% 的像素从未被采样；`tiny-islands` 桌面端 99.6% 浪费。
4. 128×128 下 **floor 是主要瓶颈**：9～31 个岛/模型卡在 3×3。
5. 桌面端与网页版**不是同一算法**：岛数差 3～7 倍，语义不同。

### 4.2 哪些原先的猜测被证伪？

1. 「提高 allocated utilization 会提升质量」——网页版 allocated 更高但 UV 更低、
   误差不更好；候选把 allocated 提到 97% 也没有带来整图质量提升。
2. 「0.85 次幂能保护小材质」——它保护中等材质，但小材质仍被 floor 卡死，
   而代价是权重不可控。
3. 「按源纹素保留（retention）默认更好」——细节材质显著变好，
   但整图误差在 2/3 个做了视角实验的模型上变差。
4. 「安全共享能显著省像素」——6 个真实模型中没有可共享的重复材质；
   合成角色只省 63 px。桌面端的激进合并省得更多，但牺牲控制。
5. 「候选应该在所有指标上优于基线」——不成立；这是目标函数不同，不是实现优劣。

### 4.3 哪种方案让材质权重真正独立且可控？

`A-density` / `A-retention` / `C` 都满足「独立」：每个材质有独立预算，
不会被其他材质合并。可预测性上：

- 相对密度严格由权重决定（数学上 `d_i/d_j = w_i/w_j`，retention 为 `r_i/r_j`）；
- 绝对响应受固定预算阻尼：4× 权重通常得到 2～3× 密度；
- floor-bound 材质无法响应，必须显式告知。

`A-density` 的响应最强（Face 4× → 9.28× 面积密度），也最容易挤占他人；
`A-retention` 更温和（2.9×），且默认更接近作者意图。

### 4.4 哪种方案在真实模型上有效纹理质量最好？

- **逐材质细节**：`A-retention` / `C` 明显最好。眼睛误差 −81%～−89%，
  面部 −13%～−49%，头发 −8%～−16%。
- **整图平均**：基线（web 或 desktop）更好；desktop 在 3/6 模型最好。
- **没有单一赢家**。如果用户在意面部/眼睛，retention + 提高权重是最有效的；
  如果只关心整图平均，legacy 的面积分配已经接近最优（因为它匹配屏幕面积）。

### 4.5 哪种方案的图集利用率最好？

`C-retention-cov`：UV 覆盖 38.8%～59.8%，5/6 模型 ≥ web，平均 +4.2 个百分点；
`allocated` 96.8%～97.8%，空像素 358～526（生产 544～1777）。
`A-retention` 的 allocated 同样高，但 furina 的 UV 覆盖明显更低。
**利用率最好 ≠ 质量最好**：furina 的 C 仍不如 desktop。

### 4.6 哪些共享是有益的，哪些妨碍精度控制？

- **有益**：源像素完全相同（同贴图、同 UV 盒、同采样参数）的材质共用矩形。
  数学上不改变任何材质的密度，只省一个矩形与 gutter。合成角色省 63 px。
- **有害**：为了装箱把不同材质的 UV 盒合并（桌面端 `mergeUvCharts` 的
  `overlapsUv` 分支）。它省空间，但把两套预算绑死，权重失效。
- **中性**：同一材质内部合并相邻岛。它不破坏独立性，但会改变该材质的
  bbox 与覆盖率；应使用更严格的阈值（增长 ≤5%、覆盖保留 ≥90%）。

### 4.7 新方案是否存在退化案例？

有，且必须保留：

1. `furina + A-retention` UV 覆盖 34.8%（见第 3 节）。
2. `lumine + A-retention` 逐材质误差变差 3.8%。
3. `nana + C` 视角误差 +9%。
4. 所有方案在 `sparse-island` 上都浪费 96%。
5. 材质数 >60 时 floor 可能无法容纳（原型会抛错；生产应给出明确提示）。

### 4.8 桌面端与网页版应该怎样复用统一核心？

已抽取 `src/atlas-core/`（纯 TS，无 DOM/Node/three/glTF）：

```
ChartInput[] → 岛分析 → 预算 → 可选安全共享 → 装箱 → PlannedChart[] + map
```

平台适配层只负责：

- 把模型转成 `ChartInput`（UV、世界面积、采样参数、贴图尺寸/身份）；
- 解码/采样/编码（sharp 或 canvas）；
- 把 `PlannedChart.map` 写回 UV。

这样两端得到**相同矩形与相同 UV 映射**，差异只剩图像重采样。
本轮的桌面端与网页端移植已经证明这条边界可行（同一渲染器下结果一致）。

### 4.9 新架构是否值得替换当前实现？

**有条件地值得，但不应该现在替换默认行为。**

- 值得替换的部分：分配、装箱、crop/整 tile 逻辑、跨材质合并、平台分叉。
- 不应立即替换的部分：默认预算目标。legacy 的面积分配在整图质量上仍然
  有竞争力，而 retention 需要用户表达优先级才有意义。
- 替换的前置条件：UI 暴露权重与 floor 提示；在更多模型（写实、硬表面）
  上验证；确认用户能理解「权重是相对量、固定预算必然此消彼长」。

## 5. 推荐的下一代架构

```
┌───────────────────────────── 共享核心 (src/atlas-core) ─────────────────────────────┐
│ 1. 几何/UV 分析：岛、世界面积、采样源纹素数、覆盖率、源感知长宽比                    │
│ 2. 预算：density（默认候选）或 retention（可选），线性权重 + 显式 floor              │
│ 3. 共享：只允许「相同源像素」的矩形复用；其余保持独立                                │
│ 4. 装箱：MaxRects + 多排序 + 有界长宽微调；预算与装箱同一搜索                        │
│ 5. 输出：矩形、UV 映射、诊断（密度、floor、浪费、共享节省）                          │
└─────────────────────────────────────────────────────────────────────────────────────┘
        │ 适配层（桌面 sharp）                    │ 适配层（浏览器 canvas）
        ▼                                         ▼
   解码 → 采样 → 编码 PNG                     drawImage / 逐像素 wrap 采样
```

保留的现有能力：`splitUvIslands` / `unwrapChartBounds` / wrap 采样 / alpha 与颜色烘焙 /
MaxRects 思路 / 确定性与可测试性。

删除的现有逻辑：compact 的 crop ±1 texel、整 tile 向下取整、跨材质 UV 合并、
`0.85` 次幂需求、两端各自的规划器。

## 6. 如果开发 UI，应该暴露哪些参数

只暴露**真实、可解释、可验证**的量：

| 参数 | 范围 | 含义 | 必须显示的反馈 |
|---|---|---|---|
| 材质纹理密度倍数 | 0.25～4（对数滑块） | 相对其他材质的 texels/m² | 预计像素数、相对倍数、是否 floor |
| 预算目标 | density / retention | 「统一清晰度」或「保留源细节」 | 一句话解释二者差异 |
| 共享相同像素材质 | 开关 | 仅合并源像素完全相同的材质 | 节省的像素数 |
| 图集尺寸 | 128（固定）/更大 | 硬预算 | 当前 floor 占用与可容纳材质数 |
| 诊断视图 | - | 矩形/UV/浪费/共享覆盖 | 每个材质的实际密度与浪费 |

不暴露：自动识别面部/眼睛/重要材质；隐式的「智能」优先级；
不可解释的 0.85 次幂或全局缩放参数。

## 7. 最终判断

- **控制性**：新模型胜出，且是结构性的（不是调参）。
- **利用率**：新模型胜出（C 最好）。
- **默认质量**：旧模型仍有优势；新模型需要用户权重才能发挥。
- **正确性**：新模型更好（去 crop、去跨材质合并、UV 越界 0、亚像素岛修复）。
- **性能**：同量级（±40% 规划时间）。
- **可维护性**：新模型把两端合并为一个核心，显著更简单。

因此：**具备「以可选模式集成」的条件，不具备「直接替换默认」的条件。**
第五阶段将只做可选集成与一致性验证，不改变默认行为。
