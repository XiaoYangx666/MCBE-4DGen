# 高面数样本的静态表情与图集预算调查

日期：2026-10-18。调查与对照均在本地进行，未部署到游戏，也未修改正式转换算法或源 PMX。

> 本文提到的实验脚本、报告与截图都位于 Git 忽略的本地目录，不属于仓库源码；可复用的诊断脚本已移到 `scripts/diagnostics/`。

## 本轮确认

1. 导入缓存中 `表情` 材质有 2078 面、alpha=1，只有 20 面退化；不能靠透明度或零面积过滤识别它。
2. 对每个表情三角形取重心和三个靠近顶点的内部点，从正面、背面和左右侧分别发射轴向射线。每方向 8312 个采样全部被其他材质的近乎不透明纹理样本遮挡，正面遮挡来自面和眼白。这是静态姿势的离散采样证据，不是所有方向/姿势的数学证明；当前管线不保留表情动画。
3. 当前图集将 `表情` 分为 20 区，内容矩形共 5474 像素，占 128² 的 33.41%。区域 82 单独占 69×71=4899 像素（29.90%）。
4. 原始表情有两面 UV 超出 1（最大 U=1.001045227、V=1.000347376）；整数 tile 范围分配及不裁切越界 UV 的路径让区域 82 走 2×2 整图平铺。不能直接 clamp UV 掩盖问题，否则会改变 REPEAT 语义。
5. `textureCharts` 合并等效材质，因此报表的 material 只是分组代表名称。`口舌` 名下的 34×30 和 35×35 大块可能包含共享贴图的脸/眼白/眉睫，不能据报表名称直接删整个分组。

## 下一步

- 静态隐藏内容过滤需要可审计的显式规则或保守检测，不能按所有模型的材质名称自动删除。
- 检查共享脸图的大 bbox 与越界 UV 分配；按实际世界表面面积/细节需求分配预算，避免源 UV 面积主导手部与丝袜预算。
- 每次对照仍需检查脸部和高分辨率参考；保持预览门槛，不能以矩形利用率宣称修复。

## 2026-10-18：循环 UV 裁切与面积预算修复

正式紧凑图集现按世界表面面积 × 材质权重分配目标矩形面积，保留 3×3 最低尺寸。不再将邻接空白随遍历顺序全部送给某个区域。负数、跨整数边界的 UV 按原 sampler 的 repeat/mirror/clamp 规则在连续区间上裁切，保持仿射映射，不直接 clamp 或逐顶点取模。对于超过 6400 万源采样像素的裁切范围仍保留旧平铺路径以限制临时内存。

几何三角形位置/法线集合 hash 与旧版本一致；没有更改减面和绑定。已检查新手部、腿部、头部预览，眼睛与正常面部仍在，色块仍可见；未部署，也未声称完成游戏内视觉验证。

网页材质列表新增相对权重（默认 1，0.05–20），结果报告新增各图集区域尺寸、像素及占比。权重影响目标面积，实际结果受最低尺寸、边距、取整、打包限制，不是固定百分比配额。新工作流回归包含负 UV 三种采样模式、跨边界颜色保留、源分辨率独立的世界面积分配与权重覆盖。

## 2026-10-18：工作台交互与导出耗时

- 材质独看只影响观察，不修改导出保留列表；支持恢复勾选视图。
- 姿势预览改为原始骨骼/权重的 Three.js 变换，不是先做完整皮肤转换。某高面数样本在 25° 外展、肩外移 0.5 的数学对照中，44025 个导出位置全部能在预览位置中找到 0.001 模型单位内的对应点。该检查没有创建浏览器。
- 面数显示为目标估算，计入双面、材质排除与人形透明壳剔除，实际值另显示；误差限制仍可能让减面停在目标以上。
- 六部位一次导出，复用图片解码。该样本相同输入/默认姿势、排除表情、ratio=.2：转换约 27926 ms → 8312 ms；面数仍为 34298。另一个 25° 姿势通过本地 HTTP 转换约 14497 ms、34306 面；请求相同参数命中缓存，mcpack 独立校验通过。不能将 8.3 秒视为所有任务的固定耗时。
- 另一样本的包间空白约 17.2% 降到 3.7%；实际非透明 UV 覆盖只从 45.5% 到 46.1%，UV 岛内留空仍明显。现在报告分别展示两个指标，不把矩形填满当成贴图真正充分使用。
- 本轮未执行网页或游戏内交互；交互与视觉效果仍需实机确认。
