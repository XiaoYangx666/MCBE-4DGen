# PMX 转换记录：样本 A 与样本 B

本文记录两个第三方 PMX 2.0 角色模型的转换结果，以「样本 A」「样本 B」代称。源模型、贴图与转换产物只在本地使用，不随仓库分发；本文不记录作品名、作者署名或本地绝对路径。两个样本均使用日文骨骼名，属于 MMD 风格资产。

## 样本与配置

| 样本 | 规模 | 衣物材质 | 说明 |
| --- | --- | --- | --- |
| A | 22,868 原始三角面 | 裙、飘带、南瓜裤、衣 | 单套衣装，裙与飘带为独立材质 |
| B | 115,661 原始面 | 服1、服2 | 两套衣装，另有 28,109 面完全透明的头发轮廓层 |

两个样本各有一份 profile（`boneMap` + 衣物规则），保存在 `profiles/sample-a.json` 与 `profiles/sample-b.json`，只记录源节点名与材质规则，不包含模型文件。新模型应从 `profiles/humanoid.example.json` 开始编写。

## 兼容路径

- 运行时统一为 Node 24+，native 与 WASM 后端均可选择，`libassimp` 锁定 0.3.0。早期 Windows Bun 环境下原生模块加载不稳定，因此曾强制使用 WASM 入口。
- 样本 B 的 PMX 附加 UV 是 VEC4。Assimp 将其写成 glTF `TEXCOORD_n`，NodeIO 因坐标类型错误拒绝。现在仅对 PMX 去掉非渲染用途的四维附加 UV，保留 UV0；若主贴图引用该附加通道会明确失败，避免静默换错贴图。回归覆盖 0/1/4 个附加通道。
- 非 VRM 通过 profile `boneMap` 明确映射源节点，而不是猜测解剖结构：hips=腰、head=頭、neck=首、upperArm=左腕/右腕、hand=左手首/右手首、shoulder=左肩/右肩；upperLeg 使用实际承载权重的 左足D/右足D。
- `rotationYDegrees=180` 把 MMD 正面转到与 Minecraft 玩家朝向一致的方向。肩外移每侧 0.3、外展 6° 是本次初始测试配置。
- Assimp 会把 PMX 展开为三角形顶点。衣物规则可用 `weldSeams=true`，仅在位置与原始关节/权重签名都一致时连接重复顶点，以恢复连通分类所需的拓扑。
- `weighted-components` 把 ≥80% 权重归同一玩家部位的连通部分整体绑定；躯干与袖子等混合部分退回逐面源权重分类，避免把连着身体的整件袖子锁死到躯干。`arm-components` 行为不变。

## 材质归属

- 样本 A：裙子 2130 面、飘带 796 面、南瓜裤 758 面整体归 body；衣材质按源连通部分/权重分组；靴子仍归腿。
- 样本 B：服1、服2 按源连通部分分组。服2 的腿部衣靴各 4432 面归左右腿，其余主体 15614 面归 body，避免把整件衣物强制绑定到腿或锁死鞋靴。

## 输出与校验

- 样本 A：原始 22,868 三角面，显式双面后 45,736。
- 样本 B：原始 115,661 面，清理后 115,626，双面后 203,145。
- 两者六个玩家部位均有非空网格，贴图 128×128；包与 mcpack 交叉校验通过，已检查实际导出文件的四视图。
- 转换报告记录源文件与 profile 的哈希、部位面数与材质分类。报告、预览和骨骼检查结果属于本地临时产物，不入库。

## 轻量版实验

测试观察：高面数版本在客户端加载困难；面数是否为原因尚未确认，也没有测到客户端硬性上限。

方法：增加独立的可选减面步骤——先完成源权重分类与姿势冻结，再按材质及六部位边界分别简化，最后烘焙贴图并生成反面。移除 `alpha=0` 的 BLEND 材质与失效的原权重分区锁；保留法线/UV 属性约束与原绑定轴心。默认转换流程不启用该步骤。

```sh
# 参数依次为：源模型、profile、输出目录、保留比例、形状容差、显示名
node scripts/workflow/reduce-avatar.ts ./sample.pmx ./profile.json ./outputs/sample-lite 0.2 0.03 'Sample Lite'
```

输出必须是新路径。结果：203,145 → 35,122 三角面，几何 JSON 28,665,702 → 5,080,633 字节，贴图仍为 128×128。已检查四视图、六部位非空与轴心一致；减面仍可能损失细节，加载与动作表现未验证。

## 紧凑图集实验

- 转换默认使用紧凑图集（机制见 [工作流程](workflow.md)），无需角色专用裁图配置。新输出使用新的库 ID，源 PMX、profile 与减面参数保持一致，最终仍为 35,122 面；模型位置/法线三角形集合及各骨骼枢轴与旧轻量版一致，仅 UV 排列与贴图改变。
- 128 图集实测：内容矩形占 81.30%，含边距分配占 99.88%；UV 三角形覆盖且 alpha>0 的像素中心从 947/16384（5.78%）提高到 4565/16384（27.86%），约 4.82 倍。前两项不能当作模型实际利用率；岛内空洞与透明区域仍有优化空间，也不保证近距离丝袜渐变完全恢复。
- 已检查完整四视图与关闭光照的手部对比，校验目录及 mcpack；类型检查与 49 项工作流回归通过。

## 色块根因对照

- 测试观察：紧凑图集后色块无明显改善，关闭光照的预览同样存在。不能把利用率提高视为问题已修复。
- 进一步做了仅本地诊断的 2048 图集（未安装到游戏），保持同一姿势/绑定，分别保留原网格与使用相同减面参数的模型。两者在高分辨率下均显示正常肤色与丝袜渐变。局部切片会在切割边界出现不整齐的几何轮廓，不能据此判断完整模型有破洞。
- 对比 PMX 原始位置/UV 与导入模型（兼容位置 Z 镜像匹配）：346,983 个导入顶点全部匹配原 UV，0 个仅在翻转 V 后才匹配，0 个未匹配。原文件含 82,080 顶点，Assimp 展开为面顶点，不代表顶点丢失。
- 最终 128 图集按 UV 三角形覆盖且 alpha>0 的像素中心计数：双手和腕部（手臂骨、Y<17.5）共 52 像素；丝袜/上腿区域（腿骨、Y>5）共 122 像素。掩码是诊断切片，不是严格解剖分割；计数也不是游戏屏幕分辨率。
- 结论：证据指向最终区域像素预算与采样损失，而不是 UV 翻转或减面单独造成的颜色错误。后续应依据部位/表面需求重新分配预算，并检查 UV 岛边缘过滤；单纯提高矩形填充率不足以修复。

## 已知限制

- 六部分刚性玩家绑定，不执行原 MMD 动作、IK、裙摆或头发物理。
- 模型显示、穿戴、待机、走路与附件穿插仍需实机确认。
- 高面数样本的客户端性能尚未测量，加载困难的具体阈值未知。
- 减面与紧凑图集会改变细节表现，不保证与原模型一致。
