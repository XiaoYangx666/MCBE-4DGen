# 工作台性能整理（2026-10-19）

- 源模型和皮肤包预览改为按需绘制。模型/纹理载入、参数变化、窗口调整和相机操作触发帧；相机阻尼继续更新至停止。静止时不维持逐帧循环，销毁时取消排队帧。
- 拖动相机不再重复遍历源模型、切换材质和检查姿势。模型状态只有在相关参数变化或载入完成时更新。
- 图片模板保留原始输入字节，读取朝向后的尺寸并直接缩到小图，避免“全尺寸 PNG 编码 → 再解码 → 缩图 PNG 编码 → 再解码”的往返。最终输出仍为 128×128 PNG；旧版本保存的 PNG 源图仍可继续编辑。
- 皮肤包列表读取一次元数据后补齐缺少的统计，不再补齐后重新读取全部条目。不引入跨请求列表缓存，其他进程的修改仍在下次请求可见。
- 同一进程的存储初始化共用一次任务，避免服务器启动和管理器配置重复扫描、复制及改写迁移记录；初始化失败可重新尝试。

## 验证证据

图片对比输入是固定种子噪声与透明像素构成的 2048×3072 PNG；同一进程交错运行优化前后实现，各 3 次。优化前约 1337/1464/1339 ms，优化后约 246/309/195 ms，中位耗时约 1.34 s → 0.25 s。逐次比较几何、解码后的最终贴图像素和源图片像素一致。时间仅代表此样本与测试环境，不代表所有图片的固定提升。

帧调度测试覆盖合并重复请求、阻尼结束、再次唤醒、销毁时取消。浏览器检查实际 WebGL draw 调用：静止预览不绘制，拖动后可重绘并恢复静止，线框变化触发源模型重绘；同时验证图片保存、重新编辑和窄屏布局。

图片回归包括透明度、比例、双面几何和带 EXIF 旋转的 JPEG，并检查保留的原图字节未改写。常规命令为 `npm run check`、`npm run check:web`、`npm run test` 和 `npm run test:studio`。

## 网页版大模型转换（2026-10-27）

- 顶点去重不再为每个角点拼字符串：`src/poly-mesh-writer.ts` 的 `VertexStream` 和 `webapp/engine/reduce.ts` 的 `weld` 改为按浮点位数做哈希分桶，精确比较后再复用索引。
- 网格提取的热循环去掉每三角面的临时数组和对象，法线、UV、角点位置复用固定缓冲（`webapp/engine/extract.ts`）。
- 图集覆盖率统计改为扫描线增量边函数，并按材质让出主线程；结果与原逐像素实现一致（随机 UV 对比：采样/UV 像素数与每个材质的像素数完全相同）。
- 几何校验的多边形热循环去掉 `Set` / `map` / `Math.hypot(...spread)` 分配（`src/geometry-validator.ts`），网页和桌面导出共用。
- 导入后第一次转换静态模型会复用导入时的网格提取结果，不再整场景重新提取（此前 `sourcePose` 的比较键少了绑定方式，永远不相等）。
- 导入与转换每 40 ms 让出一次主线程，阶段文字和当前材质持续刷新；`webapp/engine/progress.ts` 统一收口阶段上报。

样本：20.48 万三角面球面网格，Node 24 单线程。提取 112 → 78 ms，减面（保留 20%）447 → 263 ms，几何导出 200 → 136 ms，合计约 759 → 477 ms（约 −37%）。浏览器内还会叠加贴图解码、图集绘制和 PNG 编码，因此绝对耗时与本机数值不同。

### PMX → GLB（主要瓶颈）

Assimp 默认后处理包含 `joinIdenticalVertices`。在 WASM 后端处理 MMD 体量的模型时，这一步会慢到分钟级：11.9 MB / 115,661 面的 PMX 转换耗时约 70.5 s / 70.4 s；去掉后为 0.84 s / 0.83 s（约 84 倍），输出的 GLB 也从 32.7 MB 降到 8.9 MB。

对比方式：同一份 PMX 和贴图，分别用默认后处理与 `['triangulate', 'sortByPrimitiveType']` 转换，再逐三角面比较位置、法线、UV（4 位/3 位小数）与所属材质。两份结果均为 115,661 面、0 个缺失、0 个多余，属性集合一致（POSITION / NORMAL / TEXCOORD_0..3 / JOINTS_0 / WEIGHTS_0）；另一个 11.3 MB 样本（115,021 面）同样完全一致。网页版从三角面汤导出，只用到三角面本身，不依赖共享顶点，因此保留 `triangulate` 与 `sortByPrimitiveType`，关闭 `joinIdenticalVertices`。
